依据项目 README 描述的全部功能，对 bvsc_tool（论文《Binary vulnerability detection based on deep learning combined with inline assembly comparison》工程实现）进行系统性功能验证，包括：

4.2 严重缺陷详情与修复建议

B1 · torch.load 兼容性（严重）

复现：python BVSC.py -efp hello_test.exe（torch 1.8.1）

ModelError: 模型权重加载失败: ...transformer.pth: 'weights_only' is an invalid
keyword argument for Unpickler()

根因：weights_only 为 torch≥2.0 新增参数，环境为 1.8.1；requirements 与实际环境脱节。

修复建议：

try:
    state_dict = torch.load(checkpoint, map_location=device, weights_only=False)
except TypeError:          # torch < 2.0
    state_dict = torch.load(checkpoint, map_location=device)

或在 requirements/pyproject 中固定 torch>=2.0 并加入安装时校验。

B2 · 发布权重与代码架构不匹配（严重）

复现：严格加载 models/transformer.pth

Missing key(s): encoder.layers.*.enc_self_attn.layer_norm.weight/bias（共 60 个键）
= 6层×(enc 2 + dec 3)个模块 × 2 参数；且词表 999 ≠ 默认 1000

根因：重构（transformer_v3.py → transformer.py）时在 MultiHeadAttention 与 PoswiseFeedForwardNet 中新增了 LayerNorm，但权重未重新训练，导致结构不一致。

修复建议（二选一）：

  1. 回退架构：删除两处 layer_norm 使代码与旧权重一致（改动小，立即可用）；或
  2. 用当前架构重新训练并重新发布权重；加载时对缺失键给出明确告警而非静默（勿用 strict=False 蒙混）。

B3 · capstone 常量误用字符串（严重）

_ARCH_MAP = {"x86": "CS_ARCH_X86"}          # 应为整数 1
_MODE_MAP = {"32": "CS_MODE_32"}            # 应为整数 2
...
self._md = Cs(_ARCH_MAP[arch], _MODE_MAP[str(mode)])   # → ctypes.ArgumentError

修复建议：

from capstone import CS_ARCH_X86, CS_MODE_32, CS_MODE_64
_ARCH_MAP = {"x86": CS_ARCH_X86}
_MODE_MAP = {"32": CS_MODE_32, "64": CS_MODE_64}

B7 · 单行内联汇编非法（严重）

复现：最小 C 程序 int main(){ __asm { nop; nop; jmp x; x: nop; } return 0; } 用 cl x86 编译 → C1004 意外文件尾；改为多行后编译通过（实验验证）。

根因：MSVC 内联汇编 { } 块中语句需换行分隔，单行分号写法会把闭合 } 吞入汇编块。

修复建议：改为多行文本：

_FLAW_ASM = "__asm {\nnop; nop;\njmp defact_flage;\ndefact_flage: nop;\n}"
_VARIABLE_ASM = "__asm {\nnop; nop;\njmp variable_flage;\nvariable_flage: nop;\n}"

B8 · 模板替换跳过条件过宽（严重）

复现：扩样文件第 76 行 inputBuffer[recvResult] = '\0'; 未替换（含 \ 被跳过）；#define CHAR_ARRAY_SIZE (3 * sizeof(data) + 2) 未替换（含 #）。声明被改名后引用仍为原名 → C2065。

根因：template.py 用 "\\" in codeline / "#" in codeline / "return" in codeline 判断「跳过行」，把字符串转义、宏定义、注释内容也误判。

修复建议：

# 仅当行尾是续行符（内联汇编续行）才跳过
if codeline.rstrip().endswith("\\"):
    continue
# 仅当行首是预处理指令才跳过（但宏体内变量仍应替换）
if codeline.lstrip().startswith("#"):
    # 对 #define 宏体执行变量替换，保留指令关键字
    ...
# 移除 "return" 判断（return 行同样需要变量替换）

B10 · LLM 客户端静态方法签名错误（严重）

@staticmethod
def _build_client(self, api_key: str):   # 多了一个 self 形参
    ...
self._client = self._build_client(api_key)  # 调用时报参数缺失

修复建议：删除 self 形参，或去掉 @staticmethod 改为实例方法。

B11 · 无良性样本导致 100% 误报（高，设计层面）

复现：对良性 hello_test.exe（246 切片）与良性对照指令串均预测为 CWE416_Use_After_Free。

根因：训练数据仅含缺陷切片（code ! S CWE_X ! CWE_X E），解码器无条件输出 CWE 标签；预测端 _CWE_PREFIX in vul_type 使任何输出都触发命中。

修复建议：

  • 训练集加入良性切片负样本（利用 -rsd / record_secure_disassembly 收集的安全切片），为词表增加 NO_VULN/BENIGN 类；
  • 或改为分类头（CLS token + softmax 二分类/多分类），弃用 seq2seq 生成式方案；
  • 评估需引入 precision/recall/F1 与真实误报率指标，而非仅训练 acc。

6. 优化建议（优先级路线图）

6.1 P0 — 立即修复（阻断性，按依赖顺序）

  1. B3 反汇编器整数常量（检测+数据集切片的第一步，先行修复）；
  2. B7 多行内联汇编 + B6 /Fo 尾斜杠 + B8 模板跳过条件 → 数据集构建全链路打通；
  3. B1 torch.load 兼容（或升级 torch）；B2 权重与架构对齐；
